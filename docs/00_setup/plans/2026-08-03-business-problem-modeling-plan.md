# 业务问题建模 Plan

## 目标

将现有业务调研和竞品调研收口为 DocAuditAgent 的自身业务模型，为后续系统架构、产品原型和数据模型设计提供共同业务边界。

## 输入

- `docs/01_business_research/business_summary.md`
- `docs/docs/02_competitive_analysis/analysis_summary.md`

## 输出文件

- `docs/03_business_problem_modeling/document_audit_business_model.md`

## 分析结构

1. 产品定位、核心业务问题与非目标。
2. 目标用户、角色职责和权限边界。
3. MVP 场景及其准入条件、业务结果和人工兜底。
4. 审核案件的主流程、状态与规则逻辑。
5. 从功能清单升级而来的概念业务数据对象及关系。
6. 向架构、原型和数据模型阶段交付的明确输入。

## 实施与验证

- 仅引用输入文档已经明确的事实与设计方向，不加入外部竞品或技术方案。
- 不创建或修改前后端代码、配置、API 或数据库实现。
- 完成后检查文档是否包含核心问题、目标用户、MVP 场景及业务数据对象，并确认输出仅位于 `docs/`。

## 风险与边界

- 本阶段只定义业务对象与规则，不确定数据字段类型、API 或前后端交互实现。
- 法律意见、自动签约批准和高风险自动放行均不属于产品目标。

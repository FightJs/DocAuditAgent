# DocAuditAgent 前端设计规范 v1.0

## 1. 目的、依据与边界

本规范把既有业务模型和核心交互链路收敛为后续前端原型与实现的输入。唯一业务依据：

- `docs/03_business_problem_modeling/document_audit_business_model.md`
- `docs/04_core_interaction_flows/interaction_flow_summary.md`

前端服务于案件提交、进度查看、风险复核、人工处置和结果获取。前端不作文件准入、解析质量、审核基线适用性、风险结论或审批权限的最终判断；这些结论以服务端返回的当前状态和授权信息为准。

本规范不定义视觉样式、组件库、路由技术、接口字段、数据表或前后端代码。

## 2. 页面清单

| 编号 | 页面/视图 | 主要角色 | 业务目的 | 主要入口 |
| --- | --- | --- | --- | --- |
| P1 | 审核案件列表 | 业务提交者、法务/合规审核者 | 查看授权案件、当前阶段和待办。 | 默认入口；操作完成后返回。 |
| P2 | 新建审核案件与上传材料 | 业务提交者 | 创建案件、选择审核范围、上传正文及附件。 | P1 的新建入口；P4 的重提入口。 |
| P3 | 案件详情与处理时间线 | 业务提交者、法务/合规审核者 | 查看当前版本、状态、材料、处理阶段、待办及历史。 | P1 条目、P2 回执、通知入口。 |
| P4 | 补件/重提材料 | 业务提交者 | 按补件要求创建新文档版本并提交。 | P3 的补件待办。 |
| P5 | 风险结果与原文证据查看 | 已授权提交者、审核者 | 查看当前有效运行的风险、定位、依据及可见结果。 | P3 结果入口；P6 风险项入口。 |
| P6 | 人工审核工作台 | 法务/合规审核者 | 接收人工待办，基于证据包复核并处置。 | P1 审核待办入口；P3 人工审核入口。 |
| P7 | 人工决定确认与交付预览 | 法务/合规审核者 | 在提交案件级或风险项处置前核对影响及可见交付内容。 | P6 的处置动作。 |

页面展示、数据范围和可执行动作由用户授权、角色权限、案件状态与当前责任共同决定。

## 3. 页面结构层次

### 3.1 P1 审核案件列表

```text
案件列表页
├── 页面标题与当前角色上下文
├── 主要操作
│   └── 新建审核案件（具备创建权限时）
├── 案件筛选/检索区域
│   └── 当前状态、当前责任和授权范围
├── 案件列表
│   └── 案件条目
│       ├── 案件标识与合同类型/审核范围
│       ├── 当前文档版本标识
│       ├── 当前业务状态和行动提示
│       ├── 当前责任主体类别或待办提示
│       ├── 最近更新时间
│       └── 进入案件详情
└── 空状态、无权限状态、加载失败状态
```

`rejected`、`parse_failed`、`agent_failed` 或待补件不得显示为审核通过或无风险；状态文案必须对应后端返回的案件当前状态。

### 3.2 P2 新建审核案件与上传材料

```text
新建案件与上传页
├── 审核范围说明
│   ├── 合同类型、交易背景或审核范围选择
│   └── 材料要求、隐私与保留提示
├── 案件基本信息
│   ├── 必要业务上下文
│   └── 版本说明
├── 材料清单
│   ├── 合同正文（primary_contract）
│   └── 支持附件（supporting_attachment）
├── 上传前反馈
│   ├── 可继续项
│   ├── 需补充项
│   └── 不可提交项及可操作原因
├── 提交区
│   └── 提交材料进入受控处理
└── 提交回执
    ├── 案件与文档版本标识
    ├── 当前处理状态
    └── 前往案件详情
```

浏览器侧反馈只辅助输入。提交成功只表示材料已受控接收，不表示解析成功、已开始审核或已获批准；文件真实性、安全、实际限制、可读性、材料完整性和版本规则由后端复核。

### 3.3 P3 案件详情与处理时间线

```text
案件详情页
├── 案件摘要
│   ├── 案件标识、合同类型、审核范围
│   ├── 当前文档版本与当前审核运行（如已创建）
│   ├── 当前状态、最近更新时间和责任主体
│   └── 当前可执行动作
├── 材料与版本区
│   ├── 当前正文与附件清单
│   ├── 材料角色、版本说明与版本关系
│   └── 历史版本入口（只读）
├── 处理进度与时间线
│   ├── 上传/准入
│   ├── 解析与质量分流
│   ├── Agent 审核与分流
│   └── 人工复核、补件、交付或归档事件
├── 状态说明与行动区
│   ├── 处理中说明
│   ├── 失败/异常说明与安全的后续指引
│   ├── 补件或重提入口
│   └── 人工审核待办入口（仅授权角色）
└── 结果入口
    └── 进入风险结果与原文证据查看
```

提交者只能看到与自身职责相关的行动状态和已授权结果，不展示内部模型轨迹、安全检测策略、他人身份或未授权案件信息。审核者可见当前版本、解析质量、审核基线、失败/重试摘要及复核所需上下文。

### 3.4 P4 补件/重提材料

```text
补件/重提页
├── 当前案件与关联版本摘要
├── 待处理请求
│   ├── 缺失材料或修改要求
│   ├── 面向提交者的原因说明
│   └── 关联材料/风险项范围（按可见性过滤）
├── 新材料上传清单
│   ├── 替换/新增的正文或附件
│   └── 新版本说明
├── 上传前反馈与提交操作
└── 新版本提交回执
    ├── 新版本标识
    ├── 历史只读说明
    └── 返回案件详情
```

补件、修改合同或审核基线变化后，必须呈现为新文档版本或新审核运行的开始，不能将历史结果显示为新版本结论。

### 3.5 P5 风险结果与原文证据查看

```text
风险结果页
├── 当前有效上下文
│   ├── 案件、当前文档版本、审核运行与审核基线标识
│   └── 当前交付/复核状态
├── 风险项列表
│   └── 单项摘要：类别、严重度、置信度、处置状态、建议动作
├── 原文与证据区
│   ├── 原文位置与上下文摘录
│   ├── 解析质量/定位可用性提示
│   └── 关联审核依据与版本
├── 结果说明
│   └── 对提交者可见的结论、待办或限制条件
└── 返回案件详情/进入人工复核
```

无原文定位或适用依据的候选结论必须标为待人工确认，不能显示为已批准依据。提交者只看经过可见性过滤的交付结果；审核者看处置所需的完整证据包。

### 3.6 P6 人工审核工作台

```text
人工审核工作台
├── 待办队列
│   └── 案件待办：案件、当前版本、合同类型、最高严重度、触发原因、等待时长、基线和责任
├── 当前案件复核区
│   ├── 当前版本和审核运行有效性确认
│   ├── 案件上下文、材料与版本关系
│   ├── 风险项、原文定位、上下文与审核依据
│   ├── 解析质量、失败/异常摘要与过程历史
│   └── 交付预览
├── 风险项处置区
│   └── 确认、编辑、标记误报、补件、转交或升级
└── 案件级处置区
    └── 同意、驳回、要求补件、转交或升级
```

最终决定前必须核验当前责任人、操作者权限、文档版本、审核运行和证据完整性。若出现新版本、运行失败、证据不完整或权限变化，最终决定入口不可用，并进入既有异常或重提链路。

### 3.7 P7 人工决定确认与交付预览

```text
人工决定确认页/弹层
├── 决定类型与影响范围
├── 当前版本、审核运行和责任人确认
├── 必填理由与关联风险项/证据/授权记录
├── 对提交者可见的交付内容预览
├── 提交决定
└── 提交结果：新案件状态、审计留痕确认、返回详情或工作台
```

“同意”仅在当前有效运行的必要风险项已处置且满足授权条件时可提交；它不表示合同无风险或自动获得签署授权。“编辑”只修订人工判断或交付说明，不得改写原始文件、证据、Agent 原始候选结果、审核基线或历史决定。

## 4. 页面跳转与状态关系

```text
P1 案件列表
├── 新建案件 → P2 上传材料 → 提交成功 → P3 案件详情
├── 打开案件 → P3 案件详情
└── 审核待办 → P6 人工审核工作台

P3 案件详情
├── 需要补件/重提 → P4 补件/重提 → P3（新版本处理中）
├── 结果可查看 → P5 风险结果与原文证据
└── 人工待办 → P6 人工审核工作台

P5 风险结果与原文证据 → 需要人工处置 → P6 人工审核工作台

P6 人工审核工作台 → 选择处置 → P7 决定确认与交付预览

P7 决定确认与交付预览
├── 同意 → P3（approved / delivered）
├── 要求补件 → P3（changes_requested）→ P4
├── 驳回 → P3（rejected）
└── 转交/升级 → P6（责任人或队列更新）
```

处理中、失败、异常和人工接手均在 P3 作为状态和待办呈现，不以页面跳转替代状态变更。`parse_failed`、`agent_failed`、`rejected` 与 `changes_requested` 必须有对应的下一步，不得跳转为“已完成”。

## 5. 核心交互规范

| 场景 | 前端交互要求 | 已继承的业务约束 |
| --- | --- | --- |
| 上传与提交 | 分类展示正文/附件；提示可继续、需补充、不可提交项；提交后进入详情。 | 每次提交形成版本；客户端校验不替代服务端准入。 |
| 处理中展示 | 以“正在读取”“正在审核”“正在人工复核”等展示当前责任和下一步。 | 处理中不代表正面审核结论。 |
| 失败与异常 | 区分准入拒绝、解析失败、Agent 失败、质量不足、规则冲突和补件；显示安全、可行动说明。 | 失败、拒绝和空结果均不等同于无风险或批准。 |
| 版本化重提 | 明示旧版本与新版本关系及历史只读；新版本按新运行处理。 | 原文或基线变化不能覆盖或复用历史结论。 |
| 风险证据查看 | 风险与原文定位、上下文、依据、状态共同展示；证据不足项标待确认。 | 无证据的候选结论不可作为放行依据。 |
| 人工处置 | 基于当前有效版本、运行和证据包；提交前确认权限、责任和理由。 | 人工是最终控制点；决定需留痕。 |
| 结果交付 | 按角色和授权范围显示结果、待办和限制。 | 提交者结果需经可见性过滤。 |

## 6. 前端状态展示规则

| 案件状态 | 面向用户的表达 | 主要可用动作 |
| --- | --- | --- |
| `created` / `uploading` | 正在创建或接收材料。 | 继续上传或查看提交进度。 |
| `accepted` / `parsing` / `ready` | 材料已接收，正在读取或准备审核。 | 查看进度与材料；等待后续处理。 |
| `agent_reviewing` / `agent_completed` / `triaged` | 正在审核或正在确认后续处理。 | 查看阶段；审核者可进入待办。 |
| `human_reviewing` | 正在由审核人员复核。 | 提交者查看状态；责任审核者进入复核。 |
| `changes_requested` | 需要补充或修改材料后重新提交。 | 提交者进入 P4。 |
| `parse_failed` / `agent_failed` | 当前处理未完成，需要重试、补件或人工处理。 | 查看服务端返回的可行动指引。 |
| `rejected` | 当前版本/案件未获批准。 | 查看授权原因与后续说明；必要时重提。 |
| `approved` / `delivered` | 人工决定已完成；可查看交付结果。 | 查看交付结果与历史。 |
| `resubmitted` | 已收到更新材料，正在重新处理。 | 查看新版本进度。 |
| `archived` | 案件已归档。 | 只读查看授权历史。 |

## 7. 后续实施承接

后续原型设计应继承本规范的页面层次、角色可见性、状态表达与跳转关系；API 规范应为案件、版本、材料、解析结果、审核运行、风险项、证据、人工决定和审计事件提供契约。前端实现不得以本规范替代服务端状态与权限判定。

# DocAuditAgent 前后端功能边界规范 v1.0

## 1. 目的、依据与边界

本规范定义 DocAuditAgent 文档审核 MVP 的前端与后端职责边界，供后续架构、API、数据模型及前后端实现承接。唯一业务依据：

- `docs/03_business_problem_modeling/document_audit_business_model.md`
- `docs/04_core_interaction_flows/interaction_flow_summary.md`

前端负责将用户授权范围内的信息组织为可理解、可操作的界面，并发起用户明确触发的业务请求；后端负责身份和权限校验、状态与版本的权威判定、文件与业务对象持久化、异步处理编排、审核结果和审计记录生成。

本规范不定义实际接口、字段类型、鉴权实现、存储方案、队列方案、模型实现或前后端代码。

## 2. 边界总则

1. **服务端权威性**：案件、文档版本、解析结果、审核基线、审核运行、风险项、证据、人工决定和审计事件的真实状态由后端维护；前端不可自行改写或推断终态。
2. **前端发起、后端裁决**：前端只发起创建、上传、补件、查看、接收待办和人工处置等用户动作；后端校验身份、权限、当前责任、版本、运行和状态转换条件后决定是否执行。
3. **版本不可覆盖**：前端提示版本关系和历史只读；后端创建新版本/新运行并保证旧记录不可被覆盖为新结论。
4. **自动化不等于批准**：前端不得将接收、解析成功、Agent 完成或空风险项呈现为批准；后端不得把这些事件写为 `approved`。`approved` 以有权限人工决定为准。
5. **最小可见性**：后端按授权和角色过滤数据；前端只展示已获授权的数据，不能以隐藏控件替代后端权限控制。
6. **无实现耦合**：前后端通过后续定义的 API 契约通信，不共享内部实现、不复制审核业务规则，也不直接访问对方运行时数据。

## 3. 前端职责

| 职责域 | 前端负责事项 | 前端不负责事项 |
| --- | --- | --- |
| 会话与页面入口 | 根据后端返回的会话/授权上下文呈现可访问页面和操作入口。 | 认证、角色授权、案件访问权或审批权限的最终判定。 |
| 案件浏览 | 呈现案件列表、当前状态、当前责任、最近更新时间、待办与历史入口。 | 聚合或改写案件真实状态、跨案件越权检索。 |
| 案件创建与上传 | 收集审核范围、业务上下文、版本说明、合同正文和附件；提供上传前辅助反馈；发起提交。 | 创建权、审核范围有效性、材料完整性、文件真实性、安全性、实际限制和幂等性的最终校验。 |
| 进度与异常展示 | 以角色可见文案呈现处理中、失败、补件和人工接手状态，并引导后续操作。 | 判断重试、解析失败原因、安全处置、人工升级，或将失败改写为通过。 |
| 结果与证据阅读 | 呈现服务端提供的当前版本、当前运行、风险项、原文定位、上下文、依据、质量信号及已授权交付内容。 | 生成、修改或确认风险结论、证据定位、解析质量与审核基线适用性。 |
| 人工审核交互 | 为授权审核者提供待办接收、证据包查看、确认/编辑/误报/补件/驳回/转交/升级的表单与确认流程。 | 自行授权审批、绕过当前责任/版本/运行校验，或改写原始证据、Agent 原始结果和历史决定。 |
| 状态同步 | 在用户进入页面、提交操作或按既定交互触发时请求最新数据，并以服务端结果更新界面。 | 将本地临时状态作为案件权威状态，或在未收到后端确认时标记终态。 |

## 4. 后端职责

| 职责域 | 后端负责事项 | 不应委托给前端的判断 |
| --- | --- | --- |
| 身份、授权与可见性 | 验证身份、案件访问范围、角色、当前责任人与审批权限；按权限过滤返回内容。 | 仅依据前端页面隐藏判断是否授权。 |
| 业务对象与状态 | 创建并维护案件、文档版本、解析结果、审核基线、审核运行、风险项、证据、人工决定和审计事件；校验状态转换。 | 由客户端本地状态决定案件终态。 |
| 上传与材料准入 | 受控接收文件；校验完整性、实际类型、大小/页数/数量策略、安全性、可打开性、材料角色、完整性和版本规则。 | 浏览器声明的文件类型、大小或客户端校验结果。 |
| 解析与质量分流 | 创建和编排异步解析任务；生成标准化文本、结构、定位锚点和质量信号；判定可继续、补件、失败或人工准入。 | 由前端依据文档展示效果认定解析成功或质量合格。 |
| 审核编排与分流 | 固定文档版本与审核基线，创建审核运行，生成候选风险项并按严重度、置信度、质量与规则条件分流。 | 由前端依据风险数量或摘要判断审核完成、风险等级或人工路由。 |
| 人工决定执法 | 校验操作者、责任、当前版本、运行、证据完整性和授权；持久化同意、编辑、误报、补件、驳回、转交、升级等决定。 | 仅因前端提交按钮可见就接受决定。 |
| 审计与历史 | 对关键状态、规则选择、版本关系和人工动作记录不可变审计事件；保留历史版本和运行只读。 | 由前端维护唯一历史或允许覆盖历史记录。 |

## 5. 后端提供给前端展示的数据

后端返回的数据以当前用户授权范围为界。前端据此展示，不自行拼接未获授权信息。

| 数据类别 | 后端提供的展示语义 | 主要前端使用位置 |
| --- | --- | --- |
| 会话与权限上下文 | 当前角色、案件访问范围、可执行动作或受限原因。 | 全局入口、案件详情、工作台、决定确认。 |
| 审核案件 | 案件标识、合同类型、审核范围、当前状态、当前责任、最近更新时间、归档状态。 | 案件列表、案件详情、待办。 |
| 文档版本与材料 | 当前版本标识、正文/附件清单、材料角色、版本说明、版本关系、历史只读标识。 | 上传回执、详情、补件、风险、复核。 |
| 准入、解析与处理状态 | 准入结论、解析任务状态、解析质量信号、处理中/失败/补件/人工升级的行动说明。 | 详情状态区、补件区、复核区。 |
| 审核基线与审核运行 | 当前运行标识、关联基线及版本、运行状态、路由原因、失败/异常摘要。 | 详情、风险结果、人工复核、决定确认。 |
| 风险项与证据 | 风险类别、严重度、置信度、处置状态、原文定位、上下文、关联依据、建议动作。 | 风险结果、人工复核、决定确认。 |
| 人工待办与决定 | 当前责任、队列/升级信息、既有决定、理由、关联风险项、时间与历史。 | 详情、人工工作台、决定确认。 |
| 交付结果与待办 | 经可见性过滤后的结论、限制条件、补件要求、可执行下一步。 | 详情、补件、风险结果。 |
| 审计时间线 | 状态变更、操作者/系统主体、时间和原因摘要。 | 案件时间线、人工复核历史。 |

服务端不向业务提交者返回内部模型轨迹、安全检测细节、其他案件信息、未核实推断或不属于其职责的人员信息；前端不得依据隐藏字段或错误信息重建这些内容。

## 6. 必须由前端发起的用户操作流程

“前端发起”表示用户通过界面明确触发请求，不表示前端拥有直接变更业务状态的权力。

| 用户操作 | 适用角色 | 前端必须完成的发起与交互 | 后端必须完成的裁决与结果 |
| --- | --- | --- | --- |
| 创建审核案件 | 业务提交者 | 收集必要业务上下文和审核范围，提交创建请求。 | 校验创建权与范围有效性，创建案件并返回标识/状态。 |
| 上传材料并提交 | 业务提交者 | 选择正文/附件角色、提供版本说明、展示前置提示、发起上传和提交。 | 受控接收、完整性/安全/可读性/材料规则校验，创建版本及解析任务或返回补件/拒绝。 |
| 查看案件与处理进度 | 已授权用户 | 请求列表、详情、状态与时间线，并按返回结果展示。 | 校验访问权，返回当前权威状态和该用户可见内容。 |
| 提交补件或新版本 | 业务提交者 | 展示待补请求、收集材料和版本说明、发起重提。 | 关联原案件、创建新版本/新运行，保留历史只读并重新进入处理链路。 |
| 查看风险与原文证据 | 已授权用户 | 请求当前有效运行的结果，联动展示风险项和返回的原文定位。 | 校验可见性，返回与当前版本/运行匹配的风险、证据和交付内容。 |
| 接收人工待办 | 法务/合规审核者 | 在工作台选择待办并明确接收。 | 校验队列权限与并发责任，分配或拒绝分配并返回当前责任。 |
| 编辑或处置风险项 | 法务/合规审核者 | 填写改判、误报、补件、转交或升级的理由及关联内容，提交确认。 | 校验权限、当前版本/运行、责任和证据条件；记录人工决定与审计事件。 |
| 提交案件级同意 | 具备批准权限的审核者 | 选择同意，确认当前版本/运行、关联处置和必填理由/授权信息后提交。 | 验证必要风险项与授权条件，写入 `approved`；不满足时拒绝并返回可行动原因。 |
| 提交案件级驳回 | 具备驳回权限的审核者 | 填写驳回范围、理由和关联证据后提交。 | 校验权限和当前上下文，写入 `rejected` 与审计记录。 |
| 转交或升级 | 法务/合规审核者 | 选择目标队列/责任类型并填写原因后提交。 | 校验转交/升级权限，更新责任与待办，并保留过程历史。 |

解析、Agent 审核、有界重试、异常分流、审核基线匹配和通知触发属于后端编排，不要求或允许前端以业务按钮直接驱动。前端只呈现后端返回的阶段、待办和后续入口。

## 7. 状态、错误与一致性边界

| 情形 | 前端行为 | 后端行为 |
| --- | --- | --- |
| 上传前检查提示通过 | 展示为辅助反馈，不承诺材料可审核。 | 在接收区进行最终校验。 |
| 服务端拒绝材料 | 显示安全且可行动的重传/补件说明，不写成审核结论。 | 记录拒绝或补件状态及原因摘要，阻止进入不应继续的处理。 |
| 解析或 Agent 处理中 | 展示阶段、责任主体类别和下一步，不假定完成时间或结果。 | 异步编排任务并更新权威状态。 |
| 解析/Agent 失败或质量不足 | 显示重试、补件或人工处理的返回指引；不显示“无风险”。 | 有界重试或建立人工待办/补件路径，保留异常摘要与审计。 |
| 用户在处理期间重提 | 明示新版本正在处理，旧版本为只读历史。 | 创建新版本/新运行，避免覆盖旧结果。 |
| 人工决定提交时发生并发变化 | 不将未确认操作展示为成功，重新获取当前上下文。 | 重新校验责任、版本、运行与状态；拒绝过期或无权决定。 |
| 数据加载或操作请求失败 | 呈现“当前信息不可用/操作未完成”及安全重试入口；不自行补造结论。 | 返回可用于安全展示的错误和当前状态，确保失败不改变审批语义。 |

## 8. 交接契约与后续输入

后续 API 规范应围绕以下业务交接建立契约，而不将内部实现泄露给前端：

| 交接 | API 与实现阶段需承接的业务关联 |
| --- | --- |
| 上传与准入 → 处理中 | 案件、文档版本、材料角色、原件身份/哈希、准入结论、解析任务、解析质量与审计事件。 |
| 处理中 → 人工审批 | 当前文档版本、审核基线、审核运行、风险项、原文定位/上下文、置信度与质量信号、异常摘要与路由原因。 |
| 人工审批 → 交付或重提 | 人工决定与理由、授权责任人、关联证据/规则、当前版本/运行、可见性过滤结果与审计记录。 |

后续前端实现以 `frontend_design_spec-v1.0.md` 的页面与交互为输入；后端实现以本规范的权威判定、异步编排、版本、审计与可见性边界为输入。任何新增合同类型、自动放行范围、外部集成或状态语义均须先更新业务文档与 Plan。

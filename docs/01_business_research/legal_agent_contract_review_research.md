# 合同/法务文档审核的 Agent 场景调研

## 1. 目标与输入

### 调研目标

明确合同/法务审核中适合由 Agent 协助完成的工作、必须保留给法务人员的决策，以及支持该流程所需的人机协作能力。目标不是让模型自动给出具有法律效力的结论，而是将资料定位、条款对照、风险归纳、任务分派和留痕等重复工作结构化，缩短首轮审查时间并提升审核一致性。

### 典型输入

| 输入类别 | 示例 | 用途 |
| --- | --- | --- |
| 待审文件 | 合同正文、附件、订单、SOW、NDA、对方修订版 | 抽取条款、比较版本、识别义务与例外 |
| 内部知识 | 合同模板、条款库、红线规则、授权矩阵、历史谈判立场 | 作为审核基线和可接受范围 |
| 外部依据 | 适用法域要求、监管指引、公开政策资料 | 辅助合规核验；需标注时效和来源 |
| 业务上下文 | 交易金额、地区、主体、产品、数据类型、签约时限 | 决定风险等级和升级路径 |

## 2. 场景目标与应用场景

| 场景 | Agent 目标 | 人工控制点 |
| --- | --- | --- |
| 收件与分流 | 识别合同类型、业务主体、适用地区及缺失材料，分派给正确队列 | 确认合同分类和优先级 |
| 首轮条款审阅 | 根据模板和红线标记偏离项，生成带原文定位的风险清单 | 法务确认风险判断与建议立场 |
| 版本比对与红线摘要 | 归纳对方改动、识别实质变化、连接到受影响的审批人 | 业务/法务决定是否接受或回谈 |
| 合规核验 | 检查数据处理、保密、制裁、出口管制、责任限制等预设规则 | 对法域适用性及例外作最终确认 |
| 履约义务提取 | 从已签合同提取到期日、通知、交付、续约和审计义务，创建提醒候选项 | 负责人确认义务归属和提醒内容 |
| 审批与审计 | 汇总依据、建议、人工决定和版本，形成可追溯审核记录 | 审批人作出有授权的放行或退回决定 |

这些场景的共同业务目标是：降低漏审和模板偏离风险、将低风险合同加速处理、让高风险事项更早进入专业人员队列，并为后续争议、内审或监管检查保留可复核证据。

## 3. 审核对象与风险维度

审核对象不应只限于合同正文。系统还需要把附件、订单、主协议与补充协议的关系纳入同一审核上下文，并提示相互冲突或引用缺失。

重点审核维度包括：

- 当事人及签约权限：主体名称、关联方、签字权限和适用实体是否一致。
- 商业范围：服务/产品描述、价格、订单优先级、交付和验收机制。
- 责任与救济：赔偿、责任上限、排除损失、违约、终止与存续条款。
- 数据与知识产权：数据处理角色、安全事件通知、数据跨境、成果归属、许可范围。
- 保密和公开：保密例外、存续期限、宣传/商标使用和披露义务。
- 合规与争议：制裁、反贿赂、出口管制、审计权、适用法律、管辖与争议解决。
- 运营义务：自动续约、通知窗口、SLA、保险、报告、记录保存和审计配合。

风险输出至少应包含：原文位置、关联依据、偏离说明、风险等级、建议动作、置信度及是否需要人工复核。没有可定位依据的结论不应被当作审核意见。

## 4. Agent 工作流建议

1. **文件解析与预检**：提取文本、附件清单、版本信息和关键元数据；若文件不可读或材料缺失，退回补件。
2. **检索与规则匹配**：按合同类型、地区和交易上下文检索获批准的模板、条款库和规则；仅使用与当前案件匹配的资料。
3. **条款级分析**：将待审条款与基准条款、红线规则及对方修订进行比较，输出可引用证据而非笼统判断。
4. **风险分级与路由**：低风险且证据充分的事项进入快速人工确认；触及红线、低置信度、例外请求或高金额交易时自动升级至指定法务人员。
5. **人工决策闭环**：审核人接受、修改、驳回或要求补充资料；其理由回写为本次案件记录，规则库更新另走治理流程。
6. **归档与履约跟踪**：保存最终版本、审批决策、证据链和义务候选项；只在负责人确认后推送提醒或下游任务。

## 5. 为什么需要 LangChain 支持人机交互流程

合同审核不是单次问答：它需要持续持有案件状态、调用受控检索/文档解析/差异比较工具、在不同风险节点暂停等待人类决定，并将决定带回下一步。因此，需要工作流层把模型能力置于明确的权限、状态和审批边界内。

LangChain 可提供模型、检索器、文档加载和工具调用的统一接口；配合 LangGraph 的状态化编排与中断/恢复能力，可实现以下人机协作机制：

| 流程能力 | 审核中的作用 | 人机交互价值 |
| --- | --- | --- |
| 受控检索（RAG） | 从批准的模板、政策和条款库获取依据 | 让审核人查看来源与适用范围，减少无依据生成 |
| 工具调用 | 执行文本提取、版本比对、规则查询、案件系统读写 | 将模型限定在授权工具和参数范围内 |
| 状态图编排 | 保存合同元数据、风险清单、证据、审核意见和当前节点 | 支持中断、恢复、重试和完整审计链 |
| 人工审批节点 | 在红线、例外、低置信度或敏感数据场景暂停 | 由有权限的人作最终判断，不以模型输出自动放行 |
| 路由与升级 | 根据风险等级、法域或金额转交对应专家 | 避免把复杂案件混入通用快速流程 |

关键决策是将 LangChain/LangGraph 定位为**协作与编排层**，而非法律意见引擎：模型只形成“待审核建议”，任何批准、签约放行、规则变更和对外法律结论均必须由授权人员完成。

## 6. 实施价值与前提

预期价值包括首轮审查的标准化、专家时间向高风险谈判集中、版本变化更易追溯，以及已签合同义务更容易被发现。实现前提是：

- 建立有版本、所有者、适用范围和生效日期的条款库与红线规则库；
- 为合同类型、法域、金额、数据敏感性定义清晰的风险分级和升级阈值；
- 将案件数据隔离、最小化访问，且只向经批准的模型/检索系统传输；
- 以人工抽检和误报/漏报复盘评估质量，而不是只以模型回答速度衡量成效。

## 7. 风险与边界

1. **法律与授权边界**：系统不能替代律师或授权签约人，尤其不能自动解释法律、批准例外或放行高风险合同。
2. **准确性边界**：检索不完整、OCR 错误、过时规则或模型幻觉均可能导致漏审；输出必须附带原文和依据，低置信度默认升级。
3. **数据保护边界**：合同可能含个人信息、商业秘密和跨境数据，需落实最小权限、加密、保留期限、供应商评估及访问审计。
4. **安全边界**：上传文档中的恶意指令、错误附件或不可信网页内容不得改变系统规则、越权调用工具或影响审批结论。
5. **治理边界**：规则库更新、提示词变更、模型升级和自动化范围扩大均应有版本控制、测试、审批和回滚机制。

## 8. 调研结论与下一阶段交付物

### 结论

最适合优先落地的是“人工主导的首轮审阅与版本比对”：Agent 负责证据化整理和风险路由，人负责判断与批准。该切入点可以先验证资料质量、规则覆盖度和人工采纳率，再谨慎扩展到履约义务提取和多系统自动化。

### 下一阶段建议

- 选择 1--2 类高频、模板成熟的合同（例如 NDA 或标准采购/服务协议）作为试点。
- 与法务共同定义红线条款、风险等级、证据展示格式和人工审批 SLA。
- 形成 API/数据契约草案：案件、文件版本、条款、证据、风险项、人工决定与审计事件。
- 制定评估集和验收指标，包括条款定位准确率、重大风险召回率、人工改写率、处理时长及安全事件数。

# 合同／法务文档审核 Agent：业务调研汇总

## 1. 汇总范围与输入

本文件仅汇总两份已完成的 Teammate 调研，不新增独立主题调研结论：

- `legal_agent_contract_review_research.md`：合同／法务审核的应用场景、工作流与人机协作建议。
- `contract_legal_audit_skeptical_review.md`：误报、漏报、人工复核、证据溯源与治理风险审查。

## 2. 共同结论

合同／法务文档审核 Agent 的合理定位是**证据化的审核辅助与风险路由系统**，而不是自动出具法律意见、自动批准例外或自动放行签约的系统。

优先适用的工作包括：

- 合同分类、材料完整性检查和分流；
- 条款与已批准模板、条款库、红线规则的比较；
- 对方版本的实质性改动摘要；
- 风险项、原文位置、依据、置信度和建议动作的结构化整理；
- 履约义务候选项的提取与人工确认。

建议从规则成熟、频率较高、边界较清晰的合同类型开始试点，例如 NDA 或标准采购／服务协议。

## 3. 审核对象与最低输入要求

审核对象应覆盖合同正文、附件、订单、SOW、数据处理协议、签署页、历史版本、红线稿、条款库、交易背景与适用规则依据。

在进入模型分析前，系统必须识别并升级以下输入问题：文件不可读、附件缺失、版本不明、草案与签署版混淆、条款库或规则过期、法域不匹配。材料不足时，输出应是“需补充或人工复核”，而不是推断性结论。

## 4. 为什么需要 LangChain／LangGraph 的人机协作流程

该场景是持续的有状态流程，而非一次问答：

```text
解析与预检 → 受控检索／规则匹配 → 条款级比对 → 风险分级
→ 人工批准、编辑、驳回或补件 → 归档、审计与履约跟踪
```

LangChain 可统一接入受控检索、文档解析、版本比对与规则查询等工具；LangGraph 可保留案件状态并在红线条款、低置信度、敏感数据、例外请求或工具失败时暂停，等待有权限的人员作出决定。人工决定及其理由应作为后续状态的一部分保存。

这套人机协作不替代服务端认证、最小权限、参数校验与审计控制；它是在这些技术控制之上，为高风险业务动作增加的决策闸门。

## 5. 核心风险与控制方向

| 风险 | 主要影响 | 最低控制要求 |
| --- | --- | --- |
| 误报 | 审核疲劳、业务延迟、绕过系统 | 置信度、影响等级、人工误报反馈与规则校准 |
| 漏报 | 关键合同风险未被升级，可能造成不可逆损失 | 附件/版本完整性门禁、关键条款覆盖校验、红线强制人工复核 |
| 错误或过期依据 | 错误法律或合规判断 | 权威来源白名单、法域与生效日期校验、可定位引用 |
| 版本错配 | 审核结果不适用于实际签署合同 | 文档指纹、版本谱系、签署版锁定与人工确认 |
| 数据与权限风险 | 商业秘密、个人信息或特权信息泄露 | 数据分类、隔离、最小权限、保留期限与访问日志 |
| 责任不清 | 模型建议被误当作法律意见或签署授权 | 明确业务、法务、合规、系统所有者与签署人的职责边界 |

## 6. 人工审核的建议分级

- **低风险**：格式或模板偏差，可由业务在完整证据包基础上确认。
- **中风险**：非标准商业条款，由条款负责人或业务与法务共同复核。
- **高风险**：责任限制、赔偿、数据跨境、知识产权、制裁/出口管制、个人信息、自动续约或强制审批事项，必须升级至法务/合规；不得因模型“未发现风险”而自动放行。

人工复核界面至少应提供原文定位、完整上下文、对比基准、检索依据、模型建议、置信度及处置理由字段。

## 7. 下一阶段输入

后续阶段应将本调研转化为可验证的设计材料：

1. 明确试点合同类型、法域和强制升级阈值。
2. 建立条款库、红线规则和权威来源的版本与所有者机制。
3. 在业务问题建模中定义案件、文件版本、条款、证据、风险项、人工决定和审计事件。
4. 在核心交互链路设计中定义人工批准、编辑、拒绝、补件与异常升级状态机。
5. 建立验收指标：关键条款召回率、误报率、证据可定位率、人工推翻率、升级时效与安全事件数。

## 3. 端到端链路覆盖

```text
创建案件 → 上传与准入 → 解析与标准化 → 审核准备
→ Agent 审核 → 分流 → 人工复核/补件 → 交付 → 归档与反馈
```

上述阶段分别由三个交付文件承接：

1. 上传、准入、解析任务创建及解析质量门槛由“上传、材料准入与解析任务创建交互链路”定义。
2. 解析与 Agent 审核期间的状态语义、失败分支、重试和强制人工分流由“文档审核中间状态与异常处理规范”定义。
3. 已进入人工队列的证据核验、处置动作、案件级决定、补件回流与交付由“人工审批状态交互链路”定义。

## 4. 跨链路交接映射

| 上游交接 | 下游承接 | 必须保持关联的既有信息 |
| --- | --- | --- |
| 上传与准入 → 中间状态处理 | 已接收材料开始解析，并进入后续审核编排 | 案件、文档版本、原件身份/哈希、材料完整性与准入结论、解析任务标识、解析质量信号、审计事件。 |
| 中间状态处理 → 人工审批 | Agent 结果或异常经分流后进入人工队列 | 当前文档版本、审核基线与审核运行、风险项、原文定位与上下文、置信度/质量信号、失败或异常摘要、路由原因。 |
| 人工审批 → 交付或重提 | 人工决定形成对外可见结果，或触发新版本处理 | 人工决定及理由、授权责任人、关联证据与规则、当前版本/运行、可见性过滤后的结果、审计记录。 |

## 5. 共同约束

- `approved` 是有权限人员基于当前有效版本、运行和证据作出的决定；处理成功、解析成功或 Agent 输出均不等同于批准。
- `rejected`、`parse_failed`、`agent_failed` 和材料待补不得表达为“已通过”或“未发现风险”。
- 文档、材料或审核基线变化后，创建新的文档版本或审核运行；历史版本、结果和人工决定只读保留。
- 高严重度、低置信度、无可定位证据、解析质量问题、规则冲突和提交者异议均按既有规范进入人工处置。
